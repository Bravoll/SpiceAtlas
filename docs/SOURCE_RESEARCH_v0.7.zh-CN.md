# v0.7 知识来源调查与接入记录

日期：2026-10-29。目标是扩大可追溯的知识候选来源，建设可按名称扩展的阅读适配层。网站被检索到、能连接、允许提取正文，以及能证明某条知识，是四个不同的判断。

## 指定搜索引擎与实际结果

通过 Google、国际 Bing、国内 Bing 的第一页 HTML 适配器直接尝试查询，最初请求上限 2 秒；随后用 8 秒记录一次恢复检查。没有绕过登录、验证或访问限制。以最终 8 秒记录为准：

| 引擎 | 实际尝试 | 结果 | 本轮跳过 |
| --- | ---: | --- | ---: |
| Google | 3 | HTTP 错误 | 181 |
| 国际 Bing | 3 | 未取得可提取的结果结构 | 181 |
| 国内 Bing | 3 | HTTP 错误 | 181 |

184 × 3 = 552 条是计划记录数，实际发送 9 次；每家连续 3 次不可用后熔断，其余 543 条明确标为 skipped。返回的可提取结果为 0，不能称为完成了 552 页成功搜索，也不能推断这些引擎在用户电脑上永久不可用。逐条查询、URL、状态、时间及跳过原因保存在 `first_pages_v07*.jsonl` 与 summary 文件。

并行完成另一组补充检索：184 条全部有查询记录，共 221 次条目查询，选出 357 条结果链接。它们来自搜索服务返回的标题、摘要和链接，明确标为 **supplemental search-service results**，没有冒充 Google／国际 Bing／国内 Bing 的第一页，也没有根据检索摘要直接生成百科正文。三个原始研究文件保留相关性、匹配范围和无合适结果的原因。

## 实时读取与渲染规则

- 统一入口 `/api/other-sources/{entry_id}/stream` 使用 NDJSON。公共 API、索引候选和可选搜索并行运行；完整解析完成后才发送 card，按完成先后排列。
- 搜索可发现更多已审阅域名中的候选；尚未列入注册表的域名不自动抓取。名称路径只是候选假设，必须通过正文检查。
- 同时最多 5 个文章任务、3 个搜索任务；每轮最多考虑 18 个通用网页候选。同域正文不重复显示。
- 默认单源 8 秒、整轮 20 秒、6 张卡片，可在设置中分别调整。超时、达到卡片上限、切换条目、用户停止或断开连接都会取消剩余异步任务。暂停服务也会停止新的工作并结束当前流。
- HTML 限 2 MB、可读正文限 160,000 字符；只允许已审阅 HTTPS 主机，拒绝私网解析、凭据 URL 和非标准端口，每次重定向重新检查。
- 抽取 article / main 等主区域，名称须出现在标题或前导正文中；末尾相关植物列表的偶然出现不算匹配。过短正文、验证页、错误页面和名称不符返回错误，不替换成虚构文章。
- 清理活动内容、站点导航、图片、控件和事件属性，保留段落、章节、表格、列表、引用与超链接。章节 ID 统一命名，内部目录跳转保留，外链规范为绝对 URL。
- 卡片注明原页、接收时间和条款；Wikimedia 保留固定版本与许可入口。通用站正文沿用原站条款，读取 API 不授予额外转载权利。卡片目前以原语言呈现。

## 真实网络抽查

`live_reader_v07.json` 记录欧芹、牛至和 `gbif-7705625` 的真实读取摘要：共返回 **7 张卡片**（3、3、1），来源为 Wikibooks、Wikispecies、GBIF；未保存返回的文章全文。多个通用 HTML 域名在本环境的直接 DNS 检查阶段未完成，已如实记录为 dns 错误。抽查期间搜索引擎关闭，因为其直接第一页检查已经另有失败记录。

这能证明公共 API 至少返回过这些内容，不能证明 19 组网站全都可读、不能保证 2 秒诊断窗口内全部完成，也不代表每个长尾条目都有对应文章。浏览器布局另以明确标注的合成正文测试，两类证据分开。

## 后续维护

用 `scripts/research_sources.py --output data/source_research/新的记录名.jsonl` 重跑指定引擎检查，并保留旧记录。新增提供方需审阅域名与访问方式，再更新注册表；正文在点击时按需读取。先人工解决名称歧义，再考虑扩展可食用或菜系结论。多种设计风格的调查不属于本次来源研究，也没有在本版中提前实施。
