# v0.3 开发记录

日期：2026-10-27。

## 这次修正

原版只有 13 个固定展签、随包正文与图像快照，缺少网页模型设置和界面语言选择。刷新失败时信息不足，也无法从大量来源目录自动扩展。

本版沿用原视觉设计，把目录改为数据库驱动，并加入网页设置、可分类的联网诊断、自动语言回退、按需正文与远程图片。

## 数据结构与请求流程

- SQLite entries 保存来源身份、学名、已知中英文名称、对应语言页面和审核状态；aliases 单独索引。
- nodes、edges、membership 表达多父分类图。递归查询使用去重，避免循环分类重复计数。
- 中文短词使用转义 LIKE，较长搜索使用 FTS5 trigram；英文无匹配时进行有界相似度检索。不是无限制语义检索。
- catalogue API 后台分页，前端每页 30 条；正文和图像不进入初始目录列表负载。
- Wiki categorymembers 分页游标、分类队列、深度与预算保存为任务状态；同一来源页／已知 Wikidata 对应项尽量合并。
- GBIF 按固定 Backbone 数据集、科键、SPECIES、ACCEPTED 和分页偏移同步，创建科／属层级。不同来源未完成全库学名消歧，因此统计称“来源记录”。
- 打开条目时查询来源正文。Wikidata 提供对应名称和页面映射，中文缺页回退英文；映射请求失败不当成缺页证据。
- 外部请求统一错误分类、User-Agent、可选代理和重试；浏览器官方 CORS 路径作为独立连接选择。
- 图像 API 返回远程 URL 和出处；默认直接显示，后台按需中转可选。已知 P18 文件名时精确读取 Commons。
- 来源搜索窗口尊重 frame 响应限制，没有剥离源站安全头的中转服务。
- 界面语言、正文优先语言与翻译目标分别设置。密钥字段仅写入，不把密钥返回浏览器。
- 翻译最多 8 个重点段落，要求链接占位符和数字完整；按来源版本、服务配置、模型与目标语言区分缓存。

## 随包范围

完成 4 个维基分类根、深度 2 的发现任务，得到 1,239 条候选目录记录；3 个指定植物科得到 17,839 条 GBIF 接受种记录；分类节点共 815。数据库是可继续维护的初始范围，不代表全球香料全集。

维基分类可能包含食品、文化或非食用主题。GBIF 是植物分类来源，不是烹饪用途来源。缺少来源支持时不生成食用、风味、产地或中文名断言，通用页面用中性展示。

打包使用 SQLite backup API 获取一致的目录数据库，不依赖未同步的 WAL。排除本机配置、虚拟环境、旧快照、已下载图片与运行正文缓存。

## 后续可扩展

- 增加经过核实的植物科和来源适配器；现有图形界面 GBIF 导入仅提供 3 科。
- 食用／风味／化学成分／菜系／包装等知识的有来源字段，以及人工核实流程。
- 多来源学名消歧、同物异名与属种关系核对，避免把目录数量当成独立物种数。
- 中文分词、拼音和语义检索；目前只检索已有名称和别名。
- 全文分段翻译、批次重试、术语表和人工译文修订。
- 从结构化知识与可复用图片生成视频章节素材包，并随包导出逐图署名。

暂未实现视频生成、自动构造数万条经人工核实的香料百科，也未承诺所有来源都能全文嵌入。
