# 发布与升级检查

1. 完成用户当前批准的版本范围，维护英文／中文 README、更新日志与中文开发说明。
2. 执行当前改动所需的后端、界面、浏览器、完整 ZIP 与增量补丁检查。说明实际网络、合成数据和本机未测边界。
3. 核对增量基线为已推送的明确提交；文件哈希、用户数据保护、依赖差异、备份与失败回退通过。未来跨多个版本的升级包必须包含完整迁移链。
4. 先交付候选包供用户验收。没有新的明确授权，不 commit、不 push。
5. 获得授权后核对实际提交和推送结果；不把本地提交当作远端推送成功。
6. **v0.7 push 成功后**，回复末尾提醒：下一阶段是 [v0.8 沉浸阅读模式](ROADMAP.zh-CN.md)。
7. **v0.8 push 成功后**，回复末尾提醒：下一阶段是路线图中的 v0.9 多语言；阿拉伯语 RTL 后续单列。

这份检查单不是 GitHub 自动下载器。当前升级器使用用户已下载的新包或补丁，不自行 fetch、改远端、安装扩展或发布软件。
